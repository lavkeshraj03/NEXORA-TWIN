## Phase 5 — evaluated numerical models

Implemented sales and product-demand forecasting with exact historical aggregation, daily/weekly history, time-ordered train/validation/test partitions, seasonal-naive baseline and fixed ridge autoregression. Validation MAE selects the model; held-out test values never enter selection or recursive test features. A minimum nonzero-training-history guard prevents empty early histories from being presented as meaningful fitted models. Optional residual bands are explicitly diagnostic and not guaranteed calibrated intervals.

Customer inactivity uses 90-day past-only recency/frequency/value/tenure features and observed future inactivity labels at disjoint training/test outcome cutoffs. A deterministic L2 logistic classifier reports precision, recall, F1, ROC-AUC and average precision against a prevalence baseline; minimum cohort/class counts are enforced. Current estimates remain explicitly uncalibrated. This is an inactivity proxy, not confirmed customer loss.

Model runs retain tenant-scoped immutable dataset/source snapshots, hashes, feature definitions, implementation versions, safe JSON artifacts, evaluation and predictions. Owner/administrator/analyst can train; only owner/administrator activates. A database partial unique index enforces one active task/product/scope version, including null product. Saved inference replays without retraining; monitoring detects changed historical sources and can evaluate closed future outcomes when imported coverage is explicitly confirmed. No pooled training, pickle loading or external AI call exists.

Calculated inventory risk uses current ledger stock, trailing recorded demand and explicit lead/incoming/safety assumptions. Past-only rolling median/MAD diagnostics expose source dates for inspection. Both are labelled separately from ML predictions. The Forecasts & risk UI includes history, an inspectable chart, baseline/test comparisons, source review, activation, monitoring and real/demo separation. A 140-day synthetic CSV is supplied for explicit import in a separate demo business; nothing is automatically seeded. See forecasting-api.md.
