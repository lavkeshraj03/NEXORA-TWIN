# Phase 1 API

`GET /api/v1/health/live` returns 200 if FastAPI handles requests. It does not contact external services.

`GET /api/v1/health/ready` returns 200 when PostgreSQL, pgvector, the expected migration revision, and Redis pass checks. Otherwise it returns 503. Shape:

```json
{
  "status": "ready",
  "checked_at": "2026-10-27T18:00:00Z",
  "version": "0.1.0",
  "checks": {
    "database": {"status": "healthy", "detail": "PostgreSQL connection verified"},
    "pgvector": {"status": "healthy", "detail": "pgvector <installed version>"},
    "migrations": {"status": "healthy", "detail": "Schema is current"},
    "redis": {"status": "healthy", "detail": "Redis connection verified"}
  }
}
```

This is an illustrative contract, not a recorded verification result. Dependency status is `healthy` or `unavailable`. Overall status is `ready` or `not_ready`.

`GET /api/health` is the Next.js same-origin proxy. It forwards readiness or responds with 503 and `status: unreachable` if the API cannot be contacted or its contract is invalid. The browser validates the runtime response before rendering it.

Errors from FastAPI use `{ "error": { "code", "message", "request_id" } }`. Validation errors do not echo user inputs. Request IDs are generated by the server, not trusted from arbitrary client headers. `X-Request-ID` is exposed through explicit CORS policy. Interactive OpenAPI documentation is at `/api/docs` outside production; raw schema is `/openapi.json`.
